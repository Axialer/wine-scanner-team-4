## 2. Архитектура пайплайна

Фото этикетки идёт так: нормализация кадра, чтение штрихкода и QR, OCR, чистка текста словарём каталога, короткий список кандидатов, затем SigLIP (`google/siglip2-base-patch16-224`) только по этому списку. Если словарь ничего не оставил, сравнение идёт по каталогу. Уверенное совпадение сразу отдаёт одну карточку.

Текст в чате (сорт, вкус, еда) идёт отдельно от фото: сначала фильтр по атрибутам каталога (цвет, сорт, сладость, еда в описании), косинус SigLIP по текстовым эмбеддингам только разбирает близкие варианты. OCR и визуальный поиск по этикетке здесь не запускаются.

Штрихкод сначала ищется в каталоге. Промах берётся из локального кэша (`index/external_cache`). Попадание в кэш в сеть не ходит.

Устройство выбирается при старте: если есть CUDA у PyTorch и ONNX Runtime, SigLIP и OCR идут на GPU. Если GPU нет, остаётся CPU, процесс не падает. На этой машине в логе старта: `Device: siglip=cpu, ocr=cpu`.

## 3. Живое демо

Адрес: http://127.0.0.1:8092/

Сервис локальный, без монтажа. Замер скорости — на этом адресе, секундомером, в одном заходе.

- Каталог. Поиск по названию, винодельне или сорту фильтрует уже загруженный список. Это не распознавание этикетки.
- Карточка вина открывается кликом по карточке.
- Распознавание. Фото: «Выбрать фото» или перетаскивание снимка в композер. Время поиска — от отправки фото до карточки в чате.
- Тот же чат, текст: например «белое совиньон к рыбе», кнопка «Подобрать».

Скриншоты: `docs/demo/catalog-desktop.png`, `catalog-mobile.png`, `chat-desktop.png`, `chat-mobile.png`.

Файл `docs/demo/site-demo.mp4` — одна непрерывная запись браузера того же пути (каталог, короткий поиск «фанагория», карточка, чат, текст «белое совиньон к рыбе» и карточки ответа). Склеек нет. Для замера фото экспертам нужен живой сервер, не ролик.

## 4. Метрики F1 top-1 и top-5

Источник: `data/eval/accuracy_latest.json` и разметка `data/eval/real_photo_labels.json`. 18 размеченных телефонных фото. В `results` первый файл продублирован, в расчёт он входит один раз. Новый прогон 18 фото не запускался.

Попадание top-1 — поле `exact: true` в json (точное совпадение slug по правилам этого прогона): 16 из 18. Два промаха не отдают карточку (`status: not_in_catalog`, `predicted_slug: null`): «Декантер. Формула Q» и «Мерло Литавщук».

Определение top-1. Запрос — одно фото с одним верным slug.

- TP = 16: карточка отдана и она exact.
- FP = 0: чужая карточка не выдавалась, оба промаха — отказ.
- FN = 2: верный slug не отдан.

Precision = 16/16 = 1. Recall = 16/18 = 0,889. F1 = 2PR/(P+R) = 16/17 = 0,941.

Accuracy 16/18 = 0,889 — это другая цифра. F1 с ней не совпадает, потому что два ответа — отказ, а не выданная карточка. Если бы отказ считался такой же ошибкой, как неверная карточка, precision совпала бы с recall и F1 был бы равен 16/18. Здесь так не считаем.

Одно фото в json помечено exact, хотя предсказанный slug — алиас: `96.31_09-09-2026_19-29-01.webp`, ожидался `aratti-kaberne-po-belomu`, вернулся `aratti-kaberne-po-belomu-1`. В разметке этот slug указан в `also`. Считаем так, как записано в json (это и есть 16/18).

Попадание top-5 — `expected_slug` есть в массиве `top` этого фото, не длиннее 5 элементов. Списки часто короче пяти: шортлист OCR был меньше. Берём то, что сохранено.

17 из 18. У «Формулы Q» верный slug стоит третьим в списке из трёх, хотя top-1 — отказ. У «Мерло Литавщук» верного slug в пяти соседях нет.

Список кандидатов есть у всех 18 фото, включая отказы. Поэтому на уровне запроса precision = recall = F1 = 17/18 = 0,944.

## 5. Дополнительная функция после поиска

В чате «Распознавание» можно написать сорт, вкус или еду. Сервис подбирает карточки каталога по тексту и пишет, почему вариант близок. На запрос «белое совиньон к рыбе» в живом интерфейсе приходят карточки белого совиньона, первая помечена «Самое близкое».

Если фото не даёт уверенной карточки, сервис не подменяет её чужим вином: статус «нет в каталоге» и похожие вина по атрибутам (сорт, цвет, сладость, регион, винодельня). На этом пути визуальные соседи SigLIP не подставляются вместо ответа.

## 6. Выводы

На 18 размеченных телефонных фото точный slug — 16/18. Два промаха те же: «Декантер. Формула Q» и «Мерло Литавщук». Сервис их не выдаёт за уверенное совпадение. У Формулы Q верный slug есть в top-5 (третье место), у Мерло Литавщук — нет.

F1 top-1 при отказе без карточки: precision 1, recall 0,889, F1 0,941. F1 top-5: 0,944 (17/18).

На этой машине инференс на CPU. В `accuracy_latest.json` прогретый проход известного фото — 2,6 с (wall 2,623). По 18 уникальным тёплым проходам того же файла медиана 3,9 с (от 2,6 до 5,2). Если на машине есть CUDA, код переключает SigLIP и OCR на GPU.
